# Docker 定时任务容器 - 需求与实现方案

## 项目概述
为 sync_url_file.py 和 sync_repo_archive.py 两个脚本构建 Docker 容器，实现定时自动执行文件同步任务。支持通过环境变量灵活配置多个定时任务。

---

## 需求分析

### 核心功能
1. **定时执行** - 基于 cron 定时执行同步脚本
2. **多任务支持** - 支持配置无限个定时任务（CRON_1_*, CRON_2_*, ...）
3. **环境变量配置** - 通过环境变量设置任务周期、命令、日志路径
4. **独立日志** - 每个任务可配置独立的日志文件
5. **配置内置** - 配置文件打包进镜像，日志通过卷挂载持久化

### 技术选型
| 组件 | 选择 | 说明 |
|------|------|------|
| 基础镜像 | alpine:3.19 | 轻量、稳定 |
| 定时工具 | busybox | 提供 crond 功能 |
| 运行时 | python3 | 执行同步脚本 |

## 环境变量配置

### 任务配置格式
每个任务通过三个环境变量配置：

| 环境变量 | 必填 | 说明 | 示例 |
|----------|------|------|------|
| CRON_{n}_SCHEDULE | 是 | 定时周期（cron 格式） | `"0 * * * *"` |
| CRON_{n}_COMMAND | 是 | 执行命令 | `"python3 sync_repo_archive.py -c config/xxx.json"` |
| CRON_{n}_LOGFILE | 否 | 日志文件路径（默认 `/var/log/cron_{n}.log`） | `"/var/log/task.log"` |

### n 的取值
从 1 开始递增，entrypoint.sh 会顺序读取直到某个编号的环境变量不存在为止。

## 配置文件

### docker-compose.yaml
```yaml
version: "3.8"

services:
  cron:
    build:
      context: ..
      dockerfile: docker/Dockerfile
    image: sync-files:latest
    container_name: sync-files
    network_mode: bridge
    environment:
      # 第一个定时任务：仓库同步
      CRON_1_SCHEDULE: "0 * * * *"
      CRON_1_COMMAND: "python3 sync_repo_archive.py -c config/sync_repo_archive.config.example.json"
      CRON_1_LOGFILE: "/var/log/sync_repo_archive.log"

      # 第二个定时任务：URL 文件同步
      CRON_2_SCHEDULE: "0 * * * *"
      CRON_2_COMMAND: "python3 sync_url_file.py -c config/sync_url_file.config.example.json"
      CRON_2_LOGFILE: "/var/log/sync_url_file.log"
    volumes:
      - /tmp/sync-files-log:/var/log:rw
    restart: unless-stopped
```

### Dockerfile
```dockerfile
FROM alpine:3.19

RUN apk add --no-cache busybox python3

COPY app /app
COPY config /app/config
COPY docker/entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh && \
    sed -i 's/\r$//' /entrypoint.sh

WORKDIR /app

ENTRYPOINT ["/entrypoint.sh"]
CMD ["crond", "-f"]
```

### entrypoint.sh
```sh
#!/bin/sh

i=1
while true; do
    schedule=$(printenv "CRON_${i}_SCHEDULE")
    command=$(printenv "CRON_${i}_COMMAND")
    logfile=$(printenv "CRON_${i}_LOGFILE")

    if [ -z "$schedule" ] || [ -z "$command" ]; then
        break
    fi

    if [ -z "$logfile" ]; then
        logfile="/var/log/cron_${i}.log"
    fi

    echo "Job $i schedule: $schedule"
    echo "Job $i command:  $command"
    echo "Job $i logfile:  $logfile"

    echo "$schedule cd /app && $command >> $logfile 2>&1" >> /etc/crontabs/root

    i=$((i + 1))
done

exec "$@"
```

## 关键实现细节

### 1. 动态 crontab 生成
entrypoint.sh 通过循环读取环境变量，动态生成 /etc/crontabs/root 文件：
- 使用 `printenv` 安全读取环境变量
- 自动编号，支持无限个任务
- 每个任务独立配置日志文件

### 2. 配置内置
- 脚本和配置文件通过 `COPY` 打包进镜像
- 配置位于 `/app/config/` 目录
- 日志通过 volumes 挂载到宿主机持久化

### 3. 日志处理
- 每个任务可独立配置日志路径
- 日志通过卷挂载持久化到宿主机
- crond 前台运行，日志输出到容器标准输出

### 4. 进程管理
- 使用 `ENTRYPOINT` + `CMD` 模式
- entrypoint.sh 生成 crontab 后执行 `exec "$@"` 启动 crond
- crond 以 PID 1 运行，正确接收容器信号

### 5. 换行符处理
- Dockerfile 中使用 `sed -i 's/\r$//'` 处理 Windows 换行符
- 确保 entrypoint.sh 在 Linux 容器中正确执行

## 使用方式

### 构建并启动
```bash
cd docker
docker-compose up -d --build
```

### 查看日志
```bash
# 容器日志（crond 输出）
docker-compose logs -f

# 任务日志（宿主机路径）
tail -f /tmp/sync-files-log/*.log
```

### 添加新任务
在 docker-compose.yaml 的 environment 中添加：
```yaml
CRON_3_SCHEDULE: "*/30 * * * *"
CRON_3_COMMAND: "python3 sync_url_file.py -c config/another.json"
CRON_3_LOGFILE: "/var/log/another.log"
```

然后重启容器：
```bash
docker-compose up -d
```

## 注意事项

1. **配置文件路径** - 容器内路径为 `/app/config/xxx.json`，已打包进镜像
2. **日志路径** - 建议统一挂载到 `/var/log`，方便管理
3. **网络模式** - 使用 `network_mode: bridge` 确保能访问外部网络
4. **权限** - 日志目录需要可写权限（rw）
5. **权限** - 确保日志目录可写，容器正常运行
