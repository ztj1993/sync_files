# URL 文件同步工具 - 需求与实现方案

## 项目概述
实现一个 Python 脚本，用于同步远程 URL 文件到本地。通过检测文件更新（ETag、Last-Modified、文件哈希），只下载有变化的文件，实现增量同步。

---

## 需求分析

### 核心功能
1. **文件更新检测** - 检测指定 URL 的文件是否有更新
2. **自动下载** - 发现更新后自动下载到本地指定路径
3. **批量检测** - 支持同时检测多个文件
4. **通用 HTTP 支持** - 支持任何 HTTP 文件地址，不限于特定平台

### 更新检测策略（优先级顺序）
| 优先级 | 检测方式 | 说明 |
|--------|----------|------|
| 1 | ETag | 最可靠，服务器返回的唯一标识 |
| 2 | Last-Modified | 次选，基于文件修改时间 |
| 3 | 文件哈希 (SHA256) | 备选，下载后计算哈希值比对 |

## 配置文件格式

### 配置参数
每个检测项包含以下字段：

```json
{
  "name": "文件别名（用于显示和状态文件命名）",
  "url": "文件的完整 HTTP URL",
  "filename": "本地保存的文件路径（可选）"
}
```

### filename 字段说明
- **可选字段**：如果不指定，将自动从 URL 提取文件名
- **路径规则**：
  - 绝对路径：直接使用（如 `C:\downloads\file.md`）
  - 相对路径（`./` 或 `../` 开头）：相对于当前工作目录
  - 仅文件名：保存到 `%TEMP%/sync_url_file/cache/`
  - 未指定：从 URL 提取文件名，保存到 `%TEMP%/sync_url_file/cache/`

### 配置示例
```json
[
  {
    "name": "VSCode README",
    "url": "https://raw.githubusercontent.com/microsoft/vscode/main/README.md",
    "filename": "./downloads/vscode-readme.md"
  },
  {
    "name": "Git-osc README",
    "url": "https://gitee.com/oschina/git-osc/raw/master/README.md"
  }
]
```

## 状态文件管理

### 存储位置
- 使用系统临时目录：`%TEMP%/sync_url_file/state/`
- 每个别名对应一个独立的 JSON 状态文件

### 状态文件命名
- 直接使用配置中的 `name` 字段
- 对不安全字符进行替换处理（如 `<>:"/\|?*` 替换为 `_`）
- 文件名长度限制为 100 字符

### 状态文件内容
```json
{
  "name": "VSCode README",
  "url": "https://raw.githubusercontent.com/microsoft/vscode/main/README.md",
  "etag": "W/\"32f0ab67d4f3...\"",
  "last_modified": "",
  "file_hash": "1b13a7f188fb...",
  "content_length": "2593",
  "last_check": "2026-04-09T12:16:56.479732",
  "filename": "./downloads/vscode-readme.md"
}
```

## 命令行使用方式

### 检测并同步单个文件
```bash
# 指定输出路径
python sync_url_file.py -n "配置文件" -u https://example.com/config.json -o ./config.json

# 不指定输出路径（自动保存到临时目录）
python sync_url_file.py -n "README" -u https://raw.githubusercontent.com/user/repo/main/README.md
```

### 使用配置文件批量检测并同步
```bash
python sync_url_file.py -c config.json
```

### 参数说明
| 参数 | 说明 | 是否必填 |
|------|------|----------|
| `-n, --name` | 文件别名（用于显示） | 否（默认使用 URL） |
| `-u, --url` | 文件 URL | 是 |
| `-o, --output` | 本地保存路径 | 否（默认保存到临时目录） |
| `-c, --config` | 配置文件路径（JSON 格式） | 否 |

## 技术实现要点

### 核心类设计
```python
class FileSync:
    - __init__(): 初始化状态文件目录和下载目录
    - _get_state_file_path(name): 根据别名生成状态文件路径
    - _sanitize_filename(filename): 文件名安全化处理
    - _extract_filename_from_url(url): 从 URL 提取文件名（失败则报错）
    - _get_download_path(filename): 获取完整的下载路径
    - _load_state(name): 加载指定别名的状态
    - _save_state(name, state): 保存状态到指定别名
    - _compute_file_hash(filepath): 计算文件 SHA256 哈希
    - _check_remote_headers(url): 获取远程文件 HTTP 头信息
    - _download_file(url, local_path): 下载文件并返回哈希
    - sync_file(name, url, filename): 同步单个文件
    - sync_multiple_files(config_list): 批量同步多个文件
```

### 关键逻辑流程
1. 读取配置文件或命令行参数
2. 对每个检测项：
   a. 验证 URL 和 filename（filename 可选）
   b. 如未指定 filename，从 URL 提取（提取失败则报错）
   c. 发送 HEAD 请求获取 ETag/Last-Modified
   d. 加载对应别名的状态文件
   e. 比对判断是否有更新
   f. 如有更新，下载文件
   g. 保存新的状态到对应别名的状态文件

### 日志输出
使用 Python 标准 `logging` 模块：
- **格式**：`%(asctime)s - %(levelname)s - %(message)s`
- **级别**：
  - `INFO`：正常信息（检查状态、下载成功等）
  - `ERROR`：错误信息（下载失败、配置错误等）

## 注意事项

1. **别名唯一性** - 每个检测项的 `name` 必须唯一，否则状态文件会冲突
2. **临时目录清理** - 系统临时目录可能会被清理，导致状态丢失
3. **网络依赖** - 需要网络连接才能检查文件头信息和下载
4. **文件权限** - 确保对目标下载目录有写入权限
5. **URL 要求** - URL 必须包含有效的文件名，否则需要手动指定 filename
