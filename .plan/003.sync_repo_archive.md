# Git 仓库 Archive 同步工具 - 需求与实现方案

## 项目概述
实现一个 Python 脚本，用于同步 Git 仓库（GitHub/Gitee/GitLab/Gitea）的 archive 到本地。通过检测仓库 commit 是否有更新，只下载有变化的仓库，自动解压到指定目录或缓存压缩包。

纯 Python 标准库实现，无需第三方依赖。

---

## 需求分析

### 核心功能
1. **仓库更新检测** - 通过 API 获取最新 commit SHA，与本地状态对比
2. **自动下载 archive** - 发现更新后自动下载仓库 archive（zip/tar.gz）
3. **自动解压** - 下载完成后自动解压到指定目录，并将内容从子目录（如 `repo-main/`）提升到目标目录
4. **压缩包缓存** - 不解压时将压缩包复制到缓存目录，支持自定义文件名
5. **批量同步** - 支持同时同步多个仓库
6. **多平台支持** - 支持 GitHub、Gitee、GitLab、Gitea
7. **可选解压** - 支持配置是否解压 archive

### 更新检测策略
通过调用各平台的 API 获取最新 commit SHA：

| 平台 | API 端点 |
|------|----------|
| GitHub | `https://api.github.com/repos/{owner}/{repo}/commits/{ref}` |
| Gitee | `https://gitee.com/api/v5/repos/{owner}/{repo}/commits/{sha}` |
| GitLab | `https://gitlab.com/api/v4/projects/{encoded_path}/repository/commits?ref_name={ref}` |
| Gitea | `{api_base}/api/v1/repos/{owner}/{repo}/commits?sha={ref}&limit=1` |

## 配置文件格式

### 配置参数
每个同步项包含以下字段：

```json
{
  "name": "仓库别名（用于显示和状态文件命名）",
  "url": "仓库的完整 HTTP URL",
  "ref": "分支/标签/Commit（可选，默认 HEAD）",
  "extract": "是否解压（可选，默认 true）",
  "extract_dir": "解压目录名称（可选，默认使用仓库名）",
  "filename": "不解压时的缓存文件名（可选，默认使用 name + 后缀）",
  "archive_format": "压缩格式 zip/tar.gz（可选，默认自动选择）",
  "api_base": "API 基础 URL（用于 Gitea 自托管，可选）"
}
```

```json

  {
    "name": "scoop-lock",

```

## 状态文件管理

### 存储位置
- 使用系统临时目录：`%TEMP%/sync_repo_archive/state/`
- 每个仓库对应一个独立的 JSON 状态文件

### 状态文件命名
- 使用 `{platform}:{owner}/{repo}:{ref}` 的哈希作为文件名
- 对不安全字符进行替换处理

### 状态文件内容
```json
{
  "name": "VSCode",
  "url": "https://github.com/microsoft/vscode",
  "ref": "main",
  "platform": "github",
  "owner": "microsoft",
  "repo": "vscode",
  "commit_sha": "abc123def456...",
  "commit_date": "2026-04-09T12:00:00Z",
  "author": "username",
  "archive_path": "C:/.../microsoft_vscode_abc123de.zip",
  "extract_path": "C:/.../sync_repo_archive/cache/vscode",
  "cache_path": "C:/.../sync_repo_archive/cache/VSCode.zip",
  "last_sync": "2026-04-09T12:16:56.479732"
}
```

## 目录结构

```
%TEMP%/sync_repo_archive/
├── state/          # 状态文件目录
├── tmp/            # 下载的 archive 文件（临时，会被清理）
└── cache/          # 解压后的仓库内容 或 不解压的压缩包
```

### 缓存目录内容示例

**解压模式（extract: true）：**
```
cache/
├── vscode/               # 解压后的目录
│   ├── README.md
│   ├── package.json
│   └── ...
└── dnspod-powershell/    # 另一个解压后的目录
    ├── README.md
    └── ...
```

**缓存模式（extract: false）：**
```
cache/
├── scoop-lock.zip        # 压缩包（自定义文件名）
├── Scoop.zip             # 压缩包（默认文件名：name.zip）
└── ...
```

## 命令行使用方式

### 同步单个仓库
```bash
# 同步默认分支并解压
python sync_repo_archive.py -n "vscode" -u https://github.com/microsoft/vscode

# 同步指定分支
python sync_repo_archive.py -n "vscode" -u https://github.com/microsoft/vscode -r main

# 指定解压目录名称
python sync_repo_archive.py -n "vscode" -u https://github.com/microsoft/vscode -e myvscode

# 指定压缩格式
python sync_repo_archive.py -n "vscode" -u https://github.com/microsoft/vscode -f zip
```

### 使用配置文件批量同步
```bash
python sync_repo_archive.py -c config.json
```

### 参数说明
| 参数 | 说明 | 是否必填 |
|------|------|----------|
| `-n, --name` | 仓库别名（用于显示） | 否（默认使用 URL） |
| `-u, --url` | 仓库 URL | 是 |
| `-r, --ref` | 分支/标签/Commit | 否（默认 HEAD） |
| `-e, --extract` | 解压目录名称 | 否（默认使用仓库名） |
| `-f, --format` | 压缩格式 (zip/tar.gz) | 否（默认自动选择） |
| `-c, --config` | 配置文件路径（JSON 格式） | 否 |

## 技术实现要点

### 核心类设计

#### RepoInfo - 仓库信息类
```python
class RepoInfo:
    - platform: 平台类型 (github/gitee/gitlab/gitea)
    - owner: 仓库所有者
    - repo: 仓库名
    - ref: 分支/标签/Commit
    - api_base: API 基础 URL
    - get_archive_url(format): 获取 archive 下载 URL
    - get_commit_api_url(): 获取 commit API URL
    - get_unique_key(): 获取唯一标识 key
```

#### RepoArchiveSync - 同步器类
```python
class RepoArchiveSync:
    - __init__(): 初始化状态文件目录、下载目录、缓存目录
    - parse_repo_url(url, ref, api_base): 解析仓库 URL
    - _get_latest_commit(repo_info): 获取最新 commit SHA
    - _download_archive(url, local_path): 下载 archive
    - _extract_archive(archive_path, extract_to): 解压 archive，将内容从子目录提升到目标目录
    - sync_repo(name, url, ...): 同步单个仓库
    - sync_multiple_repos(config_list): 批量同步
```

### 支持的 URL 格式

| 平台 | URL 格式示例 |
|------|--------------|
| GitHub | `https://github.com/owner/repo` |
| Gitee | `https://gitee.com/owner/repo` |
| GitLab | `https://gitlab.com/owner/repo` |
| Gitea | `https://gitea.example.com/owner/repo` |

### Archive URL 格式

| 平台 | Archive URL 格式 |
|------|------------------|
| GitHub | `https://github.com/{owner}/{repo}/archive/{ref}.zip` |
| Gitee | `https://gitee.com/{owner}/{repo}/repository/archive/{ref}` |
| GitLab | `https://gitlab.com/{owner}/{repo}/-/archive/{ref}/{repo}-{ref}.zip` |
| Gitea | `{api_base}/{owner}/{repo}/archive/{ref}.zip` |

### 关键逻辑流程
1. 读取配置文件或命令行参数
2. 对每个仓库：
   a. 解析 URL，识别平台和仓库信息
   b. 调用 API 获取最新 commit SHA
   c. 加载对应仓库的状态文件
   d. 比对 commit SHA 判断是否有更新
   e. 如有更新，下载 archive 到 tmp 目录
   f. 如 `extract` 为 true，解压到 cache 目录（将内容从子目录提升到目标目录）
   g. 如 `extract` 为 false，复制压缩包到 cache 目录（使用 `filename` 或默认 `name.zip`）
   h. 保存新的状态

### 解压逻辑
解压时会自动处理 GitHub/GitLab 等平台的 archive 结构：
- 原始结构：`vscode-main/README.md`, `vscode-main/package.json` ...
- 解压后结构：`vscode/README.md`, `vscode/package.json` ...

如果解压失败，会自动清理已创建的目录。

### 缓存逻辑
当 `extract: false` 时：
- 如果配置了 `filename`，使用配置的文件名
- 如果没有配置，使用 `{name}.{format}`（如 `scoop-lock.zip`）
- 文件名会经过安全处理，替换不安全字符
- 压缩包从 tmp 目录复制到 cache 目录

## 注意事项

1. **API 限制** - GitHub 等平台的 API 有请求频率限制，频繁同步可能触发限制
2. **网络依赖** - 需要网络连接才能调用 API 和下载 archive
3. **存储空间** - archive 文件和解压后的文件会占用磁盘空间
4. **临时目录清理** - 系统临时目录可能会被清理，导致状态丢失
5. **Gitea 自托管** - 使用 Gitea 自托管时需要正确配置 `api_base`
6. **私有仓库** - 当前版本不支持需要认证的私有仓库
7. **解压失败处理** - 解压失败时会自动清理已创建的目录
8. **文件名安全** - 缓存文件名会自动处理不安全字符
